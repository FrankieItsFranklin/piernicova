## Как выбирали вид
1. Клиент — Restauracja Piernicova, Toruń (реальный, в базе нет). Факты: `BRIEF.md`.
2. Три первых экрана (design-kb: материал → отрисовка в полную силу → показать до правок), `docs/directions/`:

## Главная надпись «Piernicova» (2026-10-21)
5 вариантов на живом hero (`shots/wordmark/{a..e}-*`, код — `shots/wordmark/variants.mjs`): A буквы-пряники с лукровой обводкой, B золочёный рельеф, C картуш формы, D сахарная пудра через трафарет, E надпись лукром от руки.
Выбран **E**: шрифт Yellowtail (next/font, `--font-yellowtail`), кремовый «лукр» с объёмом из слоёв тени, наклон −3°. При загрузке надпись один раз «выдавливается» слева направо (clip-path, 1.7 с, класс `.piped`); при prefers-reduced-motion — сразу целиком. Тиснёная `.carved` больше нигде не используется в hero.
Гейт (production): axe 0 (1440, 390), прокрутки вбок нет, reduced-motion: анимации нет. Снимки: `shots/wordmark/final-*`.
**Анимация письма — пробовали и убрали.** Были три подхода: шторка слева направо; прорисовка по скелету шрифта (маска из осевых линий, вычисленных в браузере); то же с обрезкой по буквам вместо маски — для WebKit. Владелец счёл результат рваным, решили: без анимации. Сейчас `Wordmark.tsx` — статичный SVG-текст Yellowtail с объёмом лукра (слои `feDropShadow`) и наклоном −3°.
Гейт: axe 0 (1440), WebKit-снимок совпадает. ВНИМАНИЕ: один раз `next build` отдал старый CSS из кэша (`.next`) — если правки в globals.css не видны после сборки, `rm -rf .next` и собрать заново.
**Надпись в кривых.** `Wordmark.tsx` теперь рисует контур (`wordmark-path.ts`), полученный из Yellowtail-Regular.ttf (Apache 2.0, Astigmatic) через opentype.js, 150 px, с кернингом; веб-шрифт Yellowtail из `layout.tsx` убран — на главной на один шрифт меньше. Отдельные файлы: `docs/logo/piernicova-wordmark.svg` (кремовый лукр с объёмом, для тёмного фона) и `piernicova-wordmark-flat.svg` (один цвет #2a190f, для печати и светлого фона). Гейт: axe 0 (1440), снимок WebKit совпадает с прежним видом.
Заметил попутно: в WebKit у бона нет зубчатого нижнего края (маска `.ticket`) — проверить отдельно.
**Отрисовка скриптом (по образцу владельца: getTotalLength → dasharray/dashoffset).** Надпись разбита на 10 контуров — по букве (`wordmark-path.ts`, opentype `getPaths`), потому что у одного составного контура браузеры по-разному ведут штрих через подконтуры. `Wordmark.tsx` (клиентский): для каждой буквы длина контура → dasharray = dashoffset = длина → переход к 0; перо идёт с постоянной скоростью (время буквы ∝ длине, всё письмо 2.4 с, старт 0.25 с), каждая буква заливается кремом (fill-opacity 0.5 с), когда её обводка почти готова. Стиль: кремовая линия 2.4 px, круглые концы, объём лукра фильтром. Состояния `data-state`: pending (до скрипта ничего не видно) → drawing; reduced-motion → static (сразу целиком); без JS — `<noscript>` показывает надпись. Проверено: WebKit (`shots/wordmark/draw-frames-webkit.png`) и Chromium — в 0 с пусто, дальше буква за буквой слева направо; axe 0 (1440, 390), прокрутки вбок нет.
**Отливка в форму (заменила отрисовку пером).** Владелец: «как будто надпись отливается в форму и потом застывает как крем». `Wordmark.tsx` (серверный, только CSS): 1) пустая форма — буквы вдавлены в дерево (тёмное дно, тень у верхнего края, светлая кромка снизу; фильтр `wm-mold`); 2) 0.3–2.5 с — жидкий лукр с волнистым фронтом и влажным бликом затекает слева направо (`wm-pour`, обрезан по буквам через `clipPath`); 3) 2.3–3.4 с — блик гаснет, буквы «застывают»: проявляется лукр с объёмом (`wm-set`). reduced-motion → сразу конечный вид. Без маски, без JS — работает и в WebKit. Проверено: WebKit (`shots/wordmark/pour-frames-webkit.png`) и Chromium, axe 0 (1440, 390), прокрутки вбок нет.
Доработка: лукр течёт **по линиям букв**, а не шторкой — 55 осевых линий (`docs/wordmark/skel.json`, скелет из `skeleton-in-browser.js` / `run.mjs`, сдвинут к контурам opentype в `pour.py`) рисуются густой кремовой струёй (ширина 28) внутри формы, каждая — когда до неё доходит общий фронт слева направо, всё за 1.5 с (0.3–1.8 с); следом мягкая шторка доливает края и точки над «i»; в 1.9–2.8 с лукр застывает. Проверено в WebKit (`shots/wordmark/pour-frames-webkit.png`): axe 0 (1440, 390), прокрутки вбок нет, reduced-motion — сразу конечный вид.
Владелец: «остаются куски, которые отрисованы с самого начала» — это была видимая пустая форма (тёмные вдавленные буквы всего слова с первой секунды). Форма убрана: до заливки на дереве ничего нет, лукр сам проявляет буквы по линиям, потом застывает. Кадры с 0.05 с: `shots/wordmark/pour-frames-webkit.png`.
Владелец: «форму оставляем» — пустая вдавленная форма вернулась (видна с начала, лукр течёт в неё по линиям). Кадры: `shots/wordmark/pour-frames-webkit.png`.
Владелец: «течёт не плавно, некоторые куски отлиты сразу, некоторые пустые до конца». Причины: короткие (почти вертикальные) линии проходили мгновенно; места, куда скелет не дотягивается, доливала только шторка с разгоном (ease) — приходила под конец. Исправлено в `pour.py` и CSS: фронт равномерный (линейный, 1.6 с), струя по каждой линии с постоянной скоростью 320 px/с, шире (32); шторка идёт сразу за струёй (0.15 с) тем же линейным темпом и только по ширине надписи. Кадры каждые 0.15 с: `shots/wordmark/pour-frames-webkit.png` — без скачков и без пустот позади фронта.
**Заливка — карта течения (заменила струи по скелету).** Владелец: «всё ещё неплавно». Струи по 55 кусочкам скелета принципиально дают рывки (кусочки с круглыми концами появляются в разных точках). Теперь: `docs/wordmark/run-flow.mjs` считает для каждой точки букв время, когда до неё дотечёт лукр, влитый с левого края (геодезическое расстояние внутри формы, Dijkstra; шаг вне буквы ×4 — так лукр перескакивает только к точкам над «i»), → `public/wordmark-flow.png` (20 КБ, 2× viewBox). `Wordmark.tsx` (клиентский): после события load рисует на canvas кремовый лукр по этой карте с мягким краем, 2.2 с, один непрерывный язык по каналам букв; затем `data-state="set"` — проявляется застывший лукр с объёмом.
